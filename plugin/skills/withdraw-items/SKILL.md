# 項目の取り下げ

`withdraw-items 320:3,7 1474:2` の形で指定された項目を、`.tmp/issue-probes/<番号>/findings.md` から取り下げる。

反証で不成立と判定したものは verify-items が扱う。このスキルは、ユーザーが読んで「これは出さない」と決めた項目を落とすためのものである。

以下の `<plugin-root>` は、この SKILL.md の2階層上として解決する。成果物の正本と編集責任は[調査成果物の扱い](../probe-workspace/SKILL.md)に従う。

## 手順

### 1. 引数の解釈

`<issue番号>:<項目番号,...>` の組を読む。番号を受け取れなければ質問し、回答を得てから進める。

指定された項目が `findings.md` に実在するかを確かめる。無い番号があれば、既に取り下げ済みか誤りかを伝えて、その番号を除いて進める。

### 2. 取り下げ

issue 番号ごとに実行する。

`verdicts.md` に取り下げの記録を先に追記する。現在のコミットのラウンドが無ければ `## <codeSha>` の見出しで開き、`### <番号> delete` の節を置く。

- 変更: 削除
- 記載判断: 記載しない

節の本文に、取り下げる項目の主張と該当箇所をそのまま書き写し、ユーザーの判断で落としたことを書く。反証で崩れたわけではない場合、その区別が後から読めるようにする。節を消したあとは、その項目が何を主張していたかはこの評決にしか残らない。

記録を書いたうえで、`findings.md` から該当する `### <番号>` の節を `#### 根拠` ごと削除する。他の節はそのまま保つ。

`issue-comment.md` に取り下げた項目への言及があれば消す。改修計画の工数合計とリスク分布も、残った項目から書き直す。

`findings.md` の `nextItem` は変えない。取り下げても番号は消費済みである。

### 3. 受け入れ

```bash
python3 <plugin-root>/scripts/check_items.py <dir>
```

- 終了コード0: 取り下げが整合した
- 終了コード1: `problems` を解消する。delete の評決を書き忘れると、その番号が「主張の残らない欠番」として検出される
- 終了コード2: `action` に従って直してから再実行する

### 4. 報告

issue 番号ごとに、取り下げた番号と残った項目数、更新後の工数合計とリスク分布を伝える。

シートへ貼る形が要る場合は `export-items <番号>` を示す。

## 更新範囲

- 書き込みは指定された issue の `findings.md`・`verdicts.md`・`issue-comment.md` に限る
- 全項目を取り下げても findings.md の front matter と各節の見出しは残す
- `coverage.json` は履歴として保つ。取り下げても、何を調べたかは変わらない
- シートへの反映は人が行う。既に転記済みなら、シート側の行も削除が要ることを報告に含める
