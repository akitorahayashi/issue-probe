# 項目の取り下げ

`withdraw-items 321:3,7 1474:2` の形で指定された項目を、`.tmp/issue-probes/<番号>/report.tsv` から取り下げる。

反証で不成立と判定したものは verify-items が扱う。このスキルは、ユーザーが読んで「これは出さない」と決めた項目を落とすためのものである。

番号は詰め直さない。欠番として残す。シートは一度貼ると行位置が固定されるため、詰め直すと転記済みの行と一覧の対応が壊れる。

以下の `<plugin-root>` は、この SKILL.md の2階層上として解決する。成果物の正本と編集責任は[調査成果物の扱い](../probe-workspace/SKILL.md)に従う。

## 手順

### 1. 引数の解釈

`<issue番号>:<項目番号,...>` の組を読む。番号を受け取れなければ質問し、回答を得てから進める。

指定された項目が `report.tsv` に実在するかを確かめる。無い番号があれば、既に取り下げ済みか誤りかを伝えて、その番号を除いて進める。

### 2. 取り下げ

issue 番号ごとに実行する。

`report.tsv` から該当行を削除する。ヘッダ行と他の行はそのまま保つ。`findings/` の `### <番号>` の節は残す。何を調べた結果その番号が使われたかは、後から辿れる必要がある。

`verdicts.md` に取り下げの記録を追記する。現在のコミットのラウンドが無ければ `## <codeSha>` の見出しで開き、`### <番号> delete` の節を置く。

- 変更: 削除
- 記載判断: 記載しない

節の本文に、取り下げた項目の主張と該当箇所をそのまま残し、ユーザーの判断で落としたことを書く。反証で崩れたわけではない場合、その区別が後から読めるようにする。

`issue-comment.md` に取り下げた項目への言及があれば消す。改修計画の工数合計とリスク分布も、残った項目から書き直す。

`findings.md` の `nextItem` は変えない。取り下げても番号は消費済みである。

### 3. 受け入れ

```bash
python3 <plugin-root>/scripts/check_rows.py <dir>
```

- 終了コード0: 取り下げが整合した
- 終了コード1: `problems` を解消する。delete の評決を書き忘れると、`findings/` に残った節が「report.tsv に無い」として検出される
- 終了コード2: `action` に従って直してから再実行する

### 4. 報告

issue 番号ごとに、取り下げた番号と残った項目数、更新後の工数合計とリスク分布を伝える。

## 更新範囲

- 書き込みは指定された issue の `report.tsv`・`verdicts.md`・`issue-comment.md` に限る
- 全項目を取り下げても `report.tsv` のヘッダ行は残す。列構成は schema.json との契約である
- `findings/` と `coverage.json` は履歴として保つ
- シートへの反映は人が行う。既に転記済みなら、シート側の行も削除が要ることを報告に含める
